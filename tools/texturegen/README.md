# Texture generator

Every texture under `src/main/resources/assets/create_nuclearindustry/textures` is
generated by this tool, so the whole art set shares one palette, one lighting direction
(top-left) and one detail language (1px outline, bevel, 2x2 bolts).

```bash
python3 tools/texturegen/generate.py                    # write into the mod
python3 tools/texturegen/generate.py --out /tmp/preview --sheet /tmp/sheet.png
```

Requires Pillow (`pip install pillow`). Output is deterministic: the same seed always
produces the same pixels, so re-running never causes spurious diffs.

| file | contents |
| --- | --- |
| `palette.py` | the colour identity - one ramp per material / energy accent |
| `pixelkit.py` | canvas + primitives (bevel, brushed metal, noise, glow, outline) |
| `common.py` | shared composites: machine casing, screens, ports, ores, trefoil |
| `blocks.py` | one function per block texture |
| `items.py` | one function per item texture, built from silhouette masks |
| `fluids.py` | animated steam still/flow (+ `.mcmeta`) |

## Conventions

* **16x16** everywhere, matching Create and vanilla.
* **Steel** = structure, **brass** = kinetic, **copper** = heat, **cryo blue** = fusion tier.
* **Ports** speak one language: cyan + arrow pointing in = input, orange + arrow pointing
  out = output; round flange for fluids, square hatch for items.
* Screens are dark glass so the lit readout reads as emissive.
* Fluid textures are near-greyscale because every fluid tints them at runtime
  (see `AllNuclearFluids`).

Some textures are constrained by their block model - notably
`heat_exchanger_pipes`, whose 2px vertical shading period exists because
`models/block/heat_exchanger.json` samples arbitrary 2px-wide columns for the tube
faces. Check the model before redesigning those.
